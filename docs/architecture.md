# 架构约定

本文只记录长期有效的职责、依赖和状态约束。具体文件、函数和执行细节以源码与测试为准。

## 组织原则

- 先按运行环境隔离，再按业务职责分模块；保持单工程，不为内部文件另建抽象层。
- 每份可变状态有明确所有者，外部通过公开命令修改。
- 核心模型与持久化格式显式定义；API 和服务类型优先从实现推导，参数类型就近声明。
- 注入驱动、存储、确认等外部能力，避免业务模块获取全局单例。

## 模块职责

下表路径均相对于 `src/`。

| 模块 | 职责 |
| --- | --- |
| `core` | 必要的领域模型、公共状态、领域错误和稳定的持久化格式 |
| `main/app` | Electron 启动、窗口生命周期、存储接入与服务组装 |
| `main/connections` | 连接配置、变更前的资源检查与汇总快照 |
| `main/sessions` | 真实会话、任务调度、查询编译与执行、取消、事务和资源释放 |
| `main/metadata` | 数据库结构与类型缓存、补全和失效 |
| `main/drivers` | PostgreSQL、MySQL 与 SSH 访问，以及驱动专用类型 |
| `main/ipc` | 请求校验、可信调用者身份、业务适配与响应包装 |
| `main/workspace`、`system`、`updater` | 分别负责工作区存取、原生系统能力和应用更新 |
| `preload` | 就地定义通道及桥接方法，向页面暴露受控 API |
| `renderer/app` | 初始化、全局同步、布局与交互组织 |
| `renderer/modules` | 业务状态、操作编排和客户端能力 |
| `renderer/components` | 通过参数和回调提供展示与交互 |

`renderer/app` 是一个包，内部目录属于应用实现；`renderer/modules` 和 `renderer/components` 下的各模块分别成包。基础 UI 使用 Base UI primitives，沉淀到本地 `components/ui`。

## 依赖边界

- 跨包使用 `@/`，只访问公共 `index.ts` / `index.tsx`；包内使用相对路径，不反向引用自身入口。路径映射统一在 `tsconfig.json` 中维护。
- 单文件 `core/database`、`core/workspace`，纯入口 `preload/bridge` 和基础 UI 子入口是公共入口的例外。
- 禁止循环依赖，包括类型依赖。业务模块不导入 `main/app` 或 `main/ipc`。
- `core` 不依赖运行端或运行环境库，不承载 IPC 通道、API 清单及连接对象。

后端业务依赖方向如下，箭头表示允许导入；各模块也可依赖 `core`：

```text
connections → sessions → metadata → drivers
                  └──────────────→ drivers
```

`sessions` 通过注入函数读取配置，`metadata` 通过注入函数访问会话，以免反向依赖。`app` 负责组装，`ipc` 负责调用适配，驱动不依赖任务调度层。

main、preload、renderer 不互相导入运行端实现。唯一的跨端公共入口是纯 `preload/bridge`：`main/ipc` 可使用定义和通道，renderer 只能引用类型。preload 只有启动入口接入 Electron，其余桥接定义保持纯净，API 类型从方法实现推导，不依赖 main。

renderer 通过 `window.main` 调用明确的方法，不获得通用 IPC 调用能力。主进程必须校验实际载荷，并从可信事件确定窗口身份；类型声明不能替代运行时校验。

## 状态与交互

- 后端拥有真实连接、会话、任务和元数据；renderer 的数据库模块只缓存和合并后端快照。
- 工作区按标签页标识管理编辑内容、查询、分页、结果和日志，外部通过公共命令操作。
- 持久化只保存可恢复的工作区配置和编辑状态，不保存结果、日志或运行中的会话与任务；恢复工作区不自动执行查询页 SQL。
- 页面负责数据适配与反馈；组件定义自身参数类型，不依赖全局工作区状态。菜单、弹窗等局部状态留在界面，需要随标签页保留的状态归工作区。
- renderer 的业务模块不依赖展示组件；跨区域交互优先使用显式回调。带业务含义的逻辑归所属模块，避免堆入通用工具目录。

生产源码遵守公共入口约束，测试可访问内部实现。依赖边界由架构测试检查；结构调整还需用相关业务测试确认行为与持久化格式保持稳定。
